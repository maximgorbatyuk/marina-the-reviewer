# Граф MR и совместимость с прежней Marina

Новый анализ использует `selectionVersion: 2`. Он сохраняет механизм отбора
прежней Marina: изменённые объявления, входящие и исходящие связи, затрагивающие
их, необходимые counterparts и родительские объявления. Полный закреплённый
snapshot остаётся источником; производный граф описывает конкретное изменение.

Сопоставление включает вызовы, возможные перемещения, объявления типов и методов,
импорты, первичные и структурные срезы, тела зависимостей и покрытие изменённых
строк. Код находится в [mr_graph.go](../internal/review/mr_graph.go),
[mr_calls.go](../internal/review/mr_calls.go),
[mr_units.go](../internal/review/mr_units.go) и
[language_neutral.go](../internal/review/language_neutral.go).

Это совместимость семантического отбора, исходников и покрытия с перечисленными
ниже исправлениями. Она не означает побайтовое совпадение промптов или текста
ограничений анализа. Совместимость сохранённых планов версии 1 проверяется
отдельно: их исполнение не запускает новый анализ и не меняет закреплённый ввод.

## Доказанные исправления прежнего анализатора

Для каждого исключения требуется ограниченный пример, результат фактического
прежнего C# анализатора, проверка исходника и отдельный регрессионный тест.
Разрешение одного исключения не распространяется на другие различия графа.

| Правило сравнения | Прежняя ошибка | Поведение CLI и регрессионная проверка |
| --- | --- | --- |
| `literal-argument-arity` | Строковый аргумент исчезал при очистке исходника; вызов мог разрешиться в перегрузку без аргументов | Реальное число аргументов сохраняется: `g("x")` соответствует перегрузке с одним аргументом. `TestJavaLiteralCallsDoNotResolveZeroArgumentOverload` |
| `try-resource-declarations` | Выражение `try (...)` могло стать методом; ложные counterparts включали неизменённый контекст в изменённый граф | Управляющая конструкция не создаёт объявление метода. `TestMRUnchangedTryResourcesDoNotCreateChangedDeclarations` |
| `nested-call-discovery` | Регулярное выражение пропускало внешний вызов с вложенным вызовом, лямбдой или другим сбалансированным выражением аргумента | Сохраняются фактические вызовы и их позиции в исходнике. `TestMRNestedCallsRetainEverySourceInvocation` |
| `interface-comment-body` | Скобка в Javadoc считалась телом метода интерфейса и меняла разрешение вызова | Исполняемое тело определяется по коду вне комментария. `TestMRGraphResolvesInheritedInterfaceAndFrameworkContracts/interface_comment` |
| `annotated-type-member-discovery` | Скобки массива в аннотации могли приниматься за начало тела типа и скрывать первый метод | Начало типа определяется вне аргументов аннотации. `TestMRTypeAnnotationArrayDoesNotHideFirstMethod` |
| `callback-invocation-declarations` | Однострочные вызовы `test`, `act`, `beforeEach` и подобных функций могли становиться объявлениями методов | Настоящие именованные функции сохраняются; вызов callback не создаёт объявление. `TestMRLanguageNeutralFunctionsKeepRealDeclarations` |

Тесты находятся в [mr_graph_test.go](../internal/review/mr_graph_test.go) и
[regression_test.go](../internal/review/regression_test.go). Исправления переноса,
восстанавливающие прежнее поведение, проверяются отдельно: области локальных
переменных и полей, вложенные типы, элементы enum, структурные срезы и безопасные
Unicode-последовательности в комментариях и литералах.

## Границы анализа

Анализ лексический. Он не доказывает компиляторную разрешимость, достижимость или
динамический dispatch. Неизвестные получатели, неоднозначные цели и неподдержанные
конструкции должны сохранять соответствующее ограничение. Применимые локальные
интерфейсы и известные framework-контракты не заменяют полный classpath.

Для исходников других языков сохраняется структурный fallback, включая реальные
именованные JS/TS-функции и объявления членов. Он не является полноценным
семантическим анализатором JavaScript или TypeScript. Наличие узла или связи само
по себе не доказывает дефект: вывод проверяется по переданному исходнику.

## Повторяемое сравнение

[parity_test.go](../internal/review/parity_test.go) содержит opt-in проверку без
GitLab, провайдера AI и рабочей базы. Нужны сохранённый snapshot и документ,
полученный фактической прежней реализацией на тех же исходниках. Пример manifest:

```json
{
  "version": 1,
  "cases": [
    {
      "name": "local-case",
      "snapshot": "/private/case/snapshot.json",
      "legacyDocument": "/private/case/legacy-document.json",
      "outputDirectory": "/private/case/new-comparison",
      "exceptions": []
    }
  ]
}
```

```sh
MARINADOREVIEW_PARITY_MANIFEST=/private/cases.json \
  go test ./internal/review -run '^TestMarinaOfflineSemanticParity$' -count=1 -v
```

Проверка нормализует технические ID и сравнивает мультимножества узлов и связей,
исходные диапазоны и содержимое срезов, контекст и покрытие. Она сохраняет
`native-document.json` и `comparison.json` в новом каталоге. Используйте новый
каталог для каждого запуска; существующие результаты не перезаписываются.

Исключение содержит точный `differenceSha256`, известное `rule`, `evidenceFile` и
его `evidenceSha256`. Файл доказательств версии 2 связывает каждую запись с
`actualSnapshotSha256` и `legacyDocumentSha256` текущего случая; соответствующие
пути и хеши обязательны. Запись также содержит название регрессионного теста,
причину, проверяемые исходные доказательства и точный список различий.

Неизвестное различие, неиспользованное исключение, повторная запись, изменённый
файл или доказательство от другого входа завершают проверку ошибкой. Хеш всего
графа не может разрешить произвольный набор различий. Тексты ограничений обоих
анализаторов записываются в отчёт и не используются как разрешение различий.

Отдельный `TestOfflineLegacyAnalysisIdentity` проверяет побайтовое совпадение
канонического JSON документа старого native-анализа по `MARINADOREVIEW_LEGACY_SNAPSHOT` и
`MARINADOREVIEW_LEGACY_PLAN`. Это отдельный контракт от сравнения нового отбора с
прежней Marina.
